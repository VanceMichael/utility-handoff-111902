# 联办台演练接口

所有服务都在本机回环地址运行，数据及组织名称均为合成演练资料。重启来源服务会复位演练资料和当次受理记录；值班台台账落在 `data/`，重启后可以接着交班。

## 运行

使用 Node.js 22.23.4。

- `npm start`：同时启动演练来源（`127.0.0.1:3100`）和值班台（`127.0.0.1:3200`）。
- `npm test`：来源契约、分项归属、回告追认和全流程演练测试。

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3200` | 值班台端口 |
| `SOURCE_PORT` | `3100` | 内置演练来源端口 |
| `SOURCE_URL` | `http://127.0.0.1:<SOURCE_PORT>` | 已有来源时改为该地址 |
| `EMBEDDED_SOURCE` | `1` | 设为 `0` 不启动内置来源 |
| `CASE_ID` | `H-406` | 台账默认诉求号 |
| `DATA_DIR` | `data/` | 台账落盘目录 |

`requests/example.json` 是业务人员提交的样例请求。

## 值班台

打开 `http://127.0.0.1:3200/`：

1. **读取热线派发**：取回 `GET /dispatch/H-406` 的分项。
2. **取企业过程**：可只取实时页、只补领 `[from, to]` 闭区间，或两者都取。
3. **分项归属表**：每个分项显示承办单位、企业工单、状态、*归属依据* 和当前处理说明。
4. **发起回告**：按分项发出；补充回告需填原回执号。
5. **交班**：页面底部及 `GET /api/handover` 列出已送回热线的回执，以及仍在社区待跟进清单上的分项。

页面之外可用的接口：`GET /api/state`、`POST /api/dispatch`、`POST /api/sync`、`POST /api/replies`、`POST /api/replies/retry`、`GET /api/handover`。

## 归属规则

分项键只在诉求内有效。住址 `affectedScope` 和服务类别只用于核对，不改变归属。改变分项归属的依据只有：

- **热线派发** `operator`：无企业工单号时的初始归属。
- **转出凭据** `handoff`：企业换班转派会另开工单，只有凭据能把新工单接回原分项；`parts` 之外的项不随单转移。
- **对方接收**：`accepted` 记录须与凭据及目标工单一致才算确认承接。接收记录先于转出记录出现时先挂起，凭据到达后重放核对。

由此：

- 转出只结束原企业责任。对方未确认承接前，分项状态为「待核实」，继续出现在 `pendingAcceptance` 和交班清单里。
- 原企业末次补报只能关自己当前持有的分项，不能把已交接的分项关回去。
- 同一张单拆给两家时，另一家的处理记录不会改写本分项的结论。
- 过程记录按投递偏移去重：实时页与补领区间重复给出同一条记录只入账一次。
- 没有凭据可判定归属时，`conflicts`（以及页面黄色警示）直接给出同时指向该分项的两个企业编号，并注明需要核实的分项。

## 回告

热线允许对不同分项分别回告，一份回告发出后有自己的回执号。

- 回告身份 `requestKey` 由第一次发送时确定。断线、超时、查询短时只有「待显示」，都用**同一身份**重投或查询；热线按身份幂等，换身份重发会产生第二份受理。
- 回执尚未可查时，回告保持 `已发送`、`receiptOpen: false`，`POST /api/replies/retry` 以原身份继续追认。
- 分项已回告「已处理」且已拿到回执后，再发必须用 `priorReceipt` 引用原回执，形成可确认的补充回告；其他分项不受影响。
- 每条回告保存 `source`：发出时的承办单位、工单、归属依据、当时有效的处理说明、相关证据和原回告正文，便于回查。
- 企业补来能改变处理结论的记录（`/enterprise/findings`）会把被更正的说明置为失效并标记「处理结论可能变化」，不会自动改写已发出的回告。

## 来源接口

- `GET /dispatch/H-406` 热线任务，分项键在诉求内有效。affectedScope 是服务地点代码。
- `GET /enterprise/live?after=8` after 是企业投递偏移。next 是本页之后的查询位置，missing 是暂不可见偏移区间。
- `GET /enterprise/replay?from=9&to=10` from、to 是闭区间投递偏移。凭证 P-16 指明承接域，源工单和目标工单各有命名空间。
- `GET /enterprise/findings` 证据号指向更正前后可核对的企业处理说明。
- `POST /hotline/replies` requestKey 为发送方的回告身份。另需 caseId、part、text，可用 priorReceipt 引用已受理回告。
- `GET /hotline/replies` 以 requestKey 查受理编号，未进入可见阶段只有受理状态。
- `POST /replay/phase` 切换演练阶段（0/1），不会清除此前受理的经办号。
